Connect your **AWS account** to Yasu using our secure CloudFormation template. This one-click deployment creates a read-only IAM role that enables Yasu to analyze your cloud costs and provide optimization recommendations.

## Prerequisites

Before connecting your AWS account, ensure you have:

- **Administrative access** to your AWS account (or permissions to create IAM roles and CloudFormation stacks)
- **Cost Explorer enabled** in your AWS account
- Access to the AWS Console

<Info>
**Security First:** Yasu uses a cross-account IAM role with read-only permissions. We cannot modify or delete any of your AWS resources.
</Info>

## Quick Setup via CloudFormation

The fastest way to connect your AWS account is through our pre-configured CloudFormation template.

<Steps>
<Step title="Navigate to Integrations">

1. Log in to your Yasu dashboard at [app.yasu.cloud](https://app.yasu.cloud)
2. Go to **Settings** → **Integrations**
3. Click **Connect AWS**

</Step>

<Step title="Deploy the CloudFormation Stack">

You'll be redirected to AWS CloudFormation with our template pre-loaded.

1. **Review the stack name** — A unique name is generated for you (e.g., `YasuIntegration-abc123`)
2. **Review the parameters** — These are automatically filled in:
   - `YasuID` — Your unique Yasu customer ID
   - `YasuHandshakeID` — A secure external ID for cross-account access
   - `YasuIamRole` — The Yasu IAM role allowed to assume the role in your account
   - `BucketName` — S3 bucket for Cost and Usage Reports
   - `ReportName` — Name for your AWS CUR report
   - `TemplateVersion` — Version of the template (currently `v0.0.2`)
3. **Scroll to the bottom** and check the acknowledgment box:
   > ☑️ I acknowledge that AWS CloudFormation might create IAM resources with custom names.
4. Click **Create stack**

<Warning>
**Do not modify the parameters** — They are pre-configured to work with your Yasu account.
</Warning>

</Step>

<Step title="Wait for Stack Creation">

The CloudFormation stack typically completes in **2-3 minutes**. You can monitor the progress in the AWS Console:

- **CREATE_IN_PROGRESS** — Stack is being created
- **CREATE_COMPLETE** — Stack created successfully

Once complete, Yasu automatically detects the connection and begins syncing your data.

</Step>

<Step title="Verify Connection in Yasu">

Return to your Yasu dashboard. You should see:

- ✅ **Connection status**: Active
- ✅ **AWS Account ID**: Your connected account
- ✅ **Data sync**: In progress

<Check>
Your first cost-saving insights will appear within **5-10 minutes** after connection.
</Check>

</Step>
</Steps>

## What the CloudFormation Template Creates

Our template creates the following resources in your AWS account:

### 1. Cross-Account IAM Role

A read-only IAM role that allows Yasu to access your cost and resource data:

```
arn:aws:iam::YOUR-ACCOUNT-ID:role/YasuCostOptimizationRole-YOUR-YASU-ID
```

The role can only be assumed by Yasu's IAM role, and only with your account's unique external ID.

### 2. IAM Policies with Read-Only Permissions

The role has the AWS-managed `ViewOnlyAccess` policy plus three inline policies. The main policy (`YasuCostOptimizationPolicy`) grants read-only access across AWS services:

| Service | Permissions | Purpose |
|---------|-------------|---------|
| Cost Explorer | `ce:Describe*`, `ce:Get*`, `ce:List*` | Cost and usage data |
| Compute Optimizer | `compute-optimizer:Describe*`, `compute-optimizer:Get*` | Right-sizing recommendations |
| EC2 | `ec2:Describe*`, `ec2:List*` | Instance, volume, and snapshot info |
| RDS | `rds:Describe*`, `rds:List*` | Database instance details |
| EKS | `eks:Describe*`, `eks:List*` | Kubernetes cluster info |
| Lambda | `lambda:Get*`, `lambda:List*` | Function configurations |
| S3 | `s3:GetBucketLocation`, `s3:GetBucketTagging`, `s3:List*` | Storage bucket information |
| CloudWatch | `cloudwatch:Get*`, `cloudwatch:List*`, `cloudwatch:Describe*` | Utilization metrics |
| Organizations | `organizations:Describe*`, `organizations:List*` | Account structure |
| Savings Plans | `savingsplans:Describe*` | Savings plan coverage |
| Pricing | `pricing:Get*`, `pricing:Describe*`, `pricing:List*` | Public AWS list prices |
| Trusted Advisor | `trustedadvisor:Get*`, `trustedadvisor:List*`, `support:DescribeTrustedAdvisorChecks`, `support:DescribeTrustedAdvisorCheckResult`, `support:DescribeTrustedAdvisorCheckSummaries`, `support:DescribeTrustedAdvisorCheckRefreshStatuses` | AWS recommendations |
| Cost Optimization Hub | `cost-optimization-hub:Get*`, `cost-optimization-hub:List*` | Consolidated AWS savings recommendations |
| Member accounts (management account only) | `sts:AssumeRole` on `YasuCostOptimizationRole-YOUR-YASU-ID` | Read the same Yasu role in your member accounts |

The same policy also contains **explicit Deny** statements. An explicit Deny overrides any Allow, including `ViewOnlyAccess`, so Yasu can never read the contents of your data stores:

| Denied action | Scope |
|---------------|-------|
| `secretsmanager:GetSecretValue` | All resources |
| `kms:Decrypt` | All resources |
| `ssm:GetParameter*` | All resources |
| `dynamodb:GetItem`, `dynamodb:Query`, `dynamodb:Scan` | All resources |
| `s3:GetObject` | Every bucket except the Yasu Cost and Usage Report bucket created by this template |

A second policy (`YasuCloudWatchMetricsReadOnly`) grants read access to Container Insights logs and Auto Scaling metrics. A third policy (`ObjectGetCostandUsageReports`) lets the role read the Cost and Usage Report files in the bucket the template creates.

None of the policies grant any action that creates, changes or deletes a resource.

### 3. Cost and Usage Report (CUR)

An S3 bucket and CUR configuration for detailed billing data (management or standalone account only):

- **Bucket**: the `BucketName` stack parameter, private with all public access blocked; objects expire after 200 days
- **Report granularity**: Hourly, including resource IDs
- **Format**: CSV, GZIP-compressed

## What Yasu Will Scan

Once connected, Yasu analyzes your AWS environment for optimization opportunities:

### Cost Optimization Insights

- **Idle EC2 Instances** — Running instances with low CPU/network utilization
- **Oversized Instances** — Instances that can be downsized based on usage patterns
- **Unattached EBS Volumes** — Volumes not connected to any instance
- **Old EBS Snapshots** — Snapshots older than retention policies
- **Unused Elastic IPs** — Static IPs not associated with running resources
- **Idle RDS Instances** — Databases with minimal connections or queries
- **Underutilized Lambda** — Functions with excess memory allocation
- **S3 Storage Classes** — Buckets that could benefit from lifecycle policies

### Savings Opportunities

- **Reserved Instance Coverage** — Recommendations for RI purchases
- **Savings Plans** — Compute and EC2 Savings Plan opportunities
- **Spot Instance Candidates** — Workloads suitable for Spot pricing

## Cost Optimization Hub Recommendations

Yasu surfaces recommendations from **AWS Cost Optimization Hub (COH)** — AWS's own consolidated recommendation engine. COH brings rightsizing, idle-resource, Reserved Instance, and Savings Plans recommendations across your organization into one place, each with an estimated monthly saving.

<Info>
COH recommendations are read through the AWS Cost Optimization Hub API. Enabling it does not add to your AWS bill.
</Info>

Two things must be true for COH recommendations to appear in Yasu:

1. **Cost Optimization Hub is enabled** (opted in) in your AWS account.
2. The **Yasu IAM role has `cost-optimization-hub` read permissions** — included in the current CloudFormation template.

### Enroll in Cost Optimization Hub

Cost Optimization Hub is an opt-in AWS service. Enable it once from your **management (payer) account** so recommendations cover your whole organization.

<Tabs>
<Tab title="AWS Console">

1. Open the **AWS Billing and Cost Management** console
2. In the left navigation, select **Cost Optimization Hub**
3. Click **Enable Cost Optimization Hub** (or **Get started**)
4. Confirm the opt-in

</Tab>
<Tab title="AWS CLI">

```bash
aws cost-optimization-hub update-enrollment-status \
  --status Active \
  --region us-east-1
```

From your management account, add `--include-member-accounts` to enroll the entire organization:

```bash
aws cost-optimization-hub update-enrollment-status \
  --status Active \
  --include-member-accounts \
  --region us-east-1
```

</Tab>
</Tabs>

<Note>
Cost Optimization Hub is a global service — its API lives in **us-east-1**, so run the command with `--region us-east-1`. After enrolling, AWS can take up to **24 hours** to generate the first recommendations.
</Note>

If you're a **new customer**, that's all you need — the CloudFormation template you deployed already grants Yasu the read permission, so COH recommendations appear automatically once AWS has generated them.

## Existing Customers: Update to the Latest Template

If you connected your AWS account before template `v0.0.2`, update your Yasu IAM role once to pick up these changes:

- **Cost Optimization Hub** read permissions (`cost-optimization-hub:Get*`, `cost-optimization-hub:List*`). Without them, COH recommendations will not appear in Yasu.
- **Strictly read-only access.** `support:*` is replaced by the four Trusted Advisor read actions, `pricing:*` is replaced by `pricing:Get*`, `pricing:Describe*` and `pricing:List*`, and the explicit Deny statements for data-plane reads are added. See [IAM Policies with Read-Only Permissions](#2-iam-policies-with-read-only-permissions).

Choose either option below.

### Option A — Update your CloudFormation stack (recommended)

Update your existing Yasu stack to the latest template. Your role ARN stays the same; only the permissions and the reported template version change.

<Tabs>
<Tab title="AWS Console">

1. Open **AWS CloudFormation**
2. Select your existing Yasu stack (named `yasu-*` or `YasuIntegration-*`)
3. Click **Update** → **Replace existing template**
4. Under **Amazon S3 URL**, paste:
   ```
   https://yasu-public.s3.eu-central-1.amazonaws.com/root/yasu-cf-template-latest.json
   ```
5. On the parameters screen, set **TemplateVersion** to `v0.0.2` and keep every other parameter value as it is
6. Click **Next** through the options screen
7. On the review screen, check **I acknowledge that AWS CloudFormation might create IAM resources with custom names**
8. Click **Update stack**

For a **member account** stack, use this template URL instead:

```
https://yasu-public.s3.eu-central-1.amazonaws.com/member/yasu-member-cf-template-v0.0.2.json
```

</Tab>
<Tab title="AWS CLI">

Replace `YOUR-STACK-NAME` with your stack's name (find it in the CloudFormation console):

```bash
aws cloudformation update-stack \
  --stack-name YOUR-STACK-NAME \
  --template-url https://yasu-public.s3.eu-central-1.amazonaws.com/root/yasu-cf-template-latest.json \
  --parameters \
      ParameterKey=YasuID,UsePreviousValue=true \
      ParameterKey=YasuHandshakeID,UsePreviousValue=true \
      ParameterKey=YasuIamRole,UsePreviousValue=true \
      ParameterKey=ReportName,UsePreviousValue=true \
      ParameterKey=BucketName,UsePreviousValue=true \
      ParameterKey=YasuPingbackArn,UsePreviousValue=true \
      ParameterKey=YasuCURExportNotificationTopicArn,UsePreviousValue=true \
      ParameterKey=TemplateVersion,ParameterValue=v0.0.2 \
      ParameterKey=TemplateUrl,ParameterValue=https://yasu-public.s3.eu-central-1.amazonaws.com/root/yasu-cf-template-v0.0.2.json \
  --capabilities CAPABILITY_NAMED_IAM \
  --region us-east-1
```

The template names its IAM role, so AWS requires `CAPABILITY_NAMED_IAM`. With `CAPABILITY_IAM` the update fails with `InsufficientCapabilities`.

</Tab>
</Tabs>

The update completes in **1–2 minutes**, ending in status **UPDATE_COMPLETE**. Nothing else in your account changes — the role keeps the same ARN, and Yasu stays connected throughout.

### Option B — Edit the policy manually

If you'd rather not update the stack, replace the role's policy directly:

1. Open **IAM → Roles** and find `YasuCostOptimizationRole-*`
2. Open the attached **YasuCostOptimizationPolicy-*** policy and click **Edit**
3. Replace the JSON with the full `YasuCostOptimizationPolicy` from [View full IAM policies](#2-iam-policies-with-read-only-permissions), with `${YasuID}` and `${BucketName}` replaced by your stack's parameter values
4. Click **Save changes**

<Note>
A manual edit is overwritten the next time the CloudFormation stack updates. Option A keeps your role in sync with the template going forward.
</Note>

### Then enroll in COH

Adding the permission lets Yasu **read** Cost Optimization Hub, but AWS only generates recommendations once COH is **enabled**. If you haven't already, [enroll in Cost Optimization Hub](#enroll-in-cost-optimization-hub) as described above.

## Troubleshooting

<AccordionGroup>
<Accordion title="Stack creation failed">

**Common causes:**

1. **Insufficient permissions** — Ensure you have `cloudformation:*`, `iam:*`, and `s3:*` permissions
2. **S3 bucket name conflict** — The bucket name must be globally unique; try again to generate a new name
3. **Service limits** — Check if you've hit IAM role limits

**Solution:** Delete the failed stack and try the connection again from Yasu.

</Accordion>

<Accordion title="Connection shows as pending">

**What to check:**

1. Verify the CloudFormation stack status is `CREATE_COMPLETE`
2. Check that the stack wasn't rolled back
3. Ensure the callback URL is accessible (no VPN/firewall blocking)

**Solution:** Wait 5 minutes, then refresh. If still pending, delete the stack and reconnect.

</Accordion>

<Accordion title="Missing cost data">

**What to check:**

1. **Cost Explorer is enabled** — Go to AWS Billing → Cost Explorer → Enable
2. **Sufficient history** — Cost Explorer needs ~24 hours to populate after first enable
3. **IAM permissions** — Verify the role has `ce:Describe*`, `ce:Get*` and `ce:List*` permissions

**Solution:** Enable Cost Explorer if needed, then wait 24 hours for data to populate.

</Accordion>

<Accordion title="Incomplete resource scan">

**What to check:**

1. **Regional coverage** — Some resources may be in regions not yet scanned
2. **API rate limits** — Large accounts may take longer to fully scan
3. **Missing permissions** — Verify all Describe permissions are in place

**Solution:** Wait for the full sync cycle (up to 6 hours for large accounts).

</Accordion>
</AccordionGroup>

## Connecting Multiple AWS Accounts

If you have multiple AWS accounts (e.g., production, staging, development), you can connect each one:

1. Go to **Settings** → **Integrations**
2. Click **Connect AWS** for each additional account
3. Deploy the CloudFormation stack in each account

<Tip>
**AWS Organizations:** If you use AWS Organizations, connect the management account first for organization-wide visibility.
</Tip>
